# Production probes route through a self service binding

Live's production probes (article fingerprint page and `/index.json`) are executed by the production Worker itself during an operator Refresh. Checkpoint D found that a plain `fetch` of the production origin from inside that Worker can never succeed (issue #56): Cloudflare treats a subrequest to the Worker's own zone as a same-zone request and routes it directly to the zone origin, bypassing the worker route entirely — and `jelementi.quz.ma` has no origin behind the Worker (worker-plus-assets only), so the request is reachable-but-erroring forever. Because "reachable but erroring" is deliberately classified as "not yet propagated" rather than a probe failure, Refresh reported `pending_deployment` indefinitely while the article was verifiably live publicly. The failure mode is invisible in local workerd and remote preview, both of which reach the zone cross-zone.

The decision is to give the Worker a service binding to itself (`SELF` in `wrangler.jsonc` and `wrangler.m2.jsonc`) and route every production probe through `SELF.fetch`, keeping the probe URLs, cache-busting, bounded retries, and evidence contract unchanged. This narrows what `Live` physically proves: a self-binding request exercises the current deployment's full worker-and-assets serving path — routing, SSR/asset dispatch, and the deployed content that produced the fingerprint and index entry — but not Cloudflare's edge DNS/TLS/route layer in front of it. No in-Worker alternative proves more: the same-zone bypass is exactly the edge layer refusing to loop back. The alternatives were an `ASSETS`-binding probe (weaker: skips the Worker's own routing and would miss `run_worker_first` regressions) and probing the deployment's workers.dev preview URL (edge-served, but of a different URL surface than production, and it reintroduces the workers.dev exposure M2 deliberately disabled). Edge-layer outages remain externally observable — `verify-remote` probes the production route from outside after deploys.

A missing `SELF` binding fails Refresh closed (503) rather than falling back to a plain origin fetch: the fallback would not error loudly but silently regress to the permanent-`pending_deployment` bug this ADR exists to prevent.
